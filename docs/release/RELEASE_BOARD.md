## Why the board is 96/97, not 97/97

The full production-target QA board (`node app/tests/qa/run.mjs`, no filter) is
recorded at `app/tests/qa/out/signal-desk-prod/qa-report.md`, whose header
reads "96/97 scenarios passed" — regenerated by commit `91d19b8` ("Wave 12A
evidence: production board 96/97"). The single failure is
`review-overlay-rewrite-instruct-and-read` in the `overlay-windows` group
(`app/tests/qa/scenarios/overlay-prod.mjs`), which exercises the Review Deck's
Read/Stop toggle: a second press of `#readButton` must post `POST
/tts/stop` rather than re-reading, and the captured request array comes back
empty (`Expected length: 1, Received length: 0`) — see
`app/tests/qa/out/signal-desk-prod/qa-report.md` around the
"review-overlay-rewrite-instruct-and-read — ❌ FAIL" heading for the exact
assertion output. The client-side toggle this scenario is driving lives in
`app/src/renderer/review-overlay.html:620` (`readButton.addEventListener`).

This is not a new regression from Wave 12A's own work (that wave's
`ui-controls-prod` scenarios are 5/5, per `docs/release/WAVE12A_UI_CONTROLS.md`
line 145) — it is the same review-overlay scenario `docs/release/DECISIONS.md`
D-0031 already tracked as unreliable. What changed on 2026-07-29 is that the
earlier hypothesis — "it only fails standalone, order-dependence inside the
full board" — no longer holds: D-0031's 2026-07-29 update records that it now
fails inside the full board too, so the director's own conclusion is that the
earlier full-board passes were "the lucky side of a race" and the scenario "is
genuinely broken... it needs a real fix, not a rerun." **This board does not
upgrade that to fixed.** Closing it means making the Review Deck's Read/Stop
toggle actually issue `POST /tts/stop` on the second press (or fixing whatever
in the main-process/request-capture path is dropping that call) and getting
three consecutive full-board green runs, not a single passing rerun.
