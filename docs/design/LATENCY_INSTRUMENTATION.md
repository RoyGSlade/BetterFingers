## 1. What must be measured

The existing counter is useful but cannot certify perceived speed. `record_pipeline_metrics` keeps the last 50 records and `/metrics` exposes summaries plus ten recent records (`server.py:226`, `:1992`, `:2016`, `:3895`) **V**. Its `total_ms` begins at `process_recording_result`'s `pipeline_t0` (`:2213`) and ends before `preview_ready` broadcast (`:2500`, `:2508`). Streaming drain already happened in the dispatcher (`:2717`). It therefore excludes capture finalization, dispatch wait, streaming drain and renderer delivery/display **V**. Recovery saving inside `DictationPipeline.run` (`backend/services/dictation_pipeline.py:162`) is within that timer on the ordinary composed path; separately time it rather than assuming all recovery paths share the boundary.

Keep separate measures: **press-to-capture-ready**, **stop-to-draft-committed**, **stop-to-review-presented**, **accept-to-output-complete**, **human review dwell**, and **clipboard restore completion**. Do not call successful input dispatch verified placement. `send_draft_by_id` marks a successful output result sent (`server.py:1480`); copy-only can succeed too (`:1289`), without observing a destination field **V**.

Each timing context follows one recording through streaming, queueing, pipeline, draft presentation and output. Carry an opaque process-session sequence in private IPC metadata; use a separate output-attempt sequence for retries. Do not derive either identifier from draft text or persistent draft/database IDs. Thread/queue handoffs preserve the same context; locks protecting its tiny append-only event buffer must never wrap business work.

### Clock discipline

Use Python `time.perf_counter_ns()`, Electron main `process.hrtime.bigint()`, and renderer `performance.now()` within their own process/clock generation. Compute durations locally and serialize finite nonnegative integer milliseconds; UTC is optional coarse session metadata, never used for elapsed time. No direct subtraction between Python, main and renderer clocks, and no division of nanosecond integers into JSON numbers before taking a bounded duration.

The first slice reports backend-local stop-to-commit and renderer-local receive-to-presentation separately. A later correlated cross-process view uses private ping/reply exchanges: main stamps `a1/a4`, backend stamps `b2/b3`; possible offset lies in `[b3-a4, b2-a1]` for the same exchange. Prefer minimum round-trip exchanges, retain the interval width and drift limit, map renderer independently, and invalidate after restart, suspend, clock discontinuity or stale synchronization. Publish a cross-process duration only with its uncertainty bounds; otherwise `unavailable`. Reject a claimed 1.5 s pass if the bound straddles the budget. Correlation IDs alone do not synchronize clocks. A controlled benchmark can additionally measure stop request to visible completion in its single observer clock, including transport overhead.

Use exclusive spans or endpoint differences for totals, nested spans for diagnosis. Sum neither concurrent streaming batch times nor stage percentiles to produce end-to-end p95. Report wall critical-path duration and decode workload separately.

## 2. Record, retention and exposure

Proposed strict schema (`schema_version=1`): ephemeral sequence, clock generation, origin enum (`interactive`/`synthetic_benchmark`), mode enum, engine/model catalog ID, effective device/compute-type enums, cold/warm/unknown, streaming flag, cleanup enabled/skipped, bounded span map `{stage, status, duration_ms}`, local end-to-end durations, cross-clock uncertainty if available, outcome enum and allowlisted reason code. Unknown stage/reason IDs are rejected, not echoed. Store start/end ticks in the ephemeral recorder only, not exported diagnostics.

**Forbidden:** audio, transcript/draft/prompt/clipboard text, content hashes, exact text lengths, real utterance duration, draft/contact/profile IDs or names, window titles/process names/paths, hotkey contents, arbitrary config, URLs, tokens, exception strings, PipelineContext and recording metadata. Model IDs come from a finite shipped catalog. Existing `chars`/`audio_seconds`/UTC recent records (`server.py:1992`) must not enter the new export. Raw-log overrides in `backend/privacy/log_redaction.py:19` never bypass this schema. Durations still reveal usage behavior: keep them local and make exporting deliberate.

Retain at most 50 completed/incomplete bounded records (≤8 KiB serialized each), plus at most 16 active contexts (≤4 KiB serialized each) with deadline eviction: combined payload capacity ≤464 KiB, hard serialized capacity ceiling 512 KiB including pending collector payloads. Use bounded compact numeric/enum buffers, not arbitrary object graphs. No automatic disk log or network telemetry. Each context caps event count (64); overflow produces `incomplete` with bounded reason. Late clipboard/UI events update the correlated record only while retained. Shutdown, privacy wipe and diagnostics reset clear both pools; privacy wipe prevents delayed completion from resurrecting a record. Retention expiry does not cancel production work. Diagnostics consumers copy snapshots quickly under a lock and aggregate outside it. Actual resident memory, including Python/container overhead and snapshots, must be measured against the separate target below; payload bytes are not a RAM measurement.

Expose through authenticated `/metrics` as additive versioned latency data, keeping existing keys compatible during migration (`server.py:3895`; `tests/test_pipeline_metrics.py`). Legacy `recent` still contains `chars`, `audio_seconds` and timestamps: the new privacy contract covers the new latency subtree, not a false assertion that all legacy fields are compliant. Exclude legacy recent data from diagnostics/support exports; retiring those fields requires an explicit compatibility migration. Runtime status gets only last processing duration, outcome and ready/unknown state; Diagnostics gets local stage chart, missing spans, warm/cold/device cohorts, sample counts and success/failure counts. Small cohorts show observations, not release evidence. Support report (`server.py::gather_support_report`, `:4913`; `backend/services/support_report.py`) includes aggregate counts/p50/p95 plus declared boundary/visibility limitations only after explicit Copy/Export; omit recent records, IDs and session times. No background upload.

Overhead **T**: ≤1 ms per successful ordinary dictation for clock/event recording, ≤0.5% p50 processing regression in matched paired runs, ≤2 MiB resident collector memory including containers/snapshot overhead, with the hard payload caps above. No per-token/chunk logging, synchronous disk I/O or new inference. Diagnostics polling throttled to 1 Hz while visible; benchmark export after runs. If instrumentation fails, production continues and the sample is incomplete; timing must not defeat cancellation/privacy release. Measure overhead with injected slow/failing collectors and instrumentation on/off before enabling by default.

## 4. Reproducible synthetic benchmark design

This card does not run the benchmark. Future harness creates a disposable user-data/profile/cache/SQLite/recovery root and launches the actual backend plus visible controlled review window with production auth. Models/runtimes must already exist, be verified and permitted by consent; disable acquisition, updates, external networking, wake, TTS after fixture generation, cloning, automatic submission and application-profile discovery. Production profile/config/cache files are read-only, with distinct auth/process/ports. Refuse a live user profile or shared existing backend; cleanup only verified owned temporary roots after processes exit.

Fixtures: original generic contributor text, no identities/PII or real recordings. `docs/TEST_DATA_POLICY.md:7`, `:19` requires synthetic provenance and a deterministic checked-in recipe for future WAVs; its existing speech-signal JSON corpus is expressly not acoustic ground truth (`:35`). Use the owner's already-installed, approved Kokoro stock voice to synthesize generic 2/10/30 s speech offline; no cloned/real-person voice. Store recipe text, stock voice/model version and asset checksums, generator version/seed, sample rate/resampling parameters, actual generated duration and WAV hash in a dedicated benchmark manifest. Do not repurpose the speech-signal manifest or check in WAVs under this task. F4 must verify model/voice rights; recipe review is required before future fixture inclusion. Hardware nondeterminism may prevent byte-identical synthesis: preserve the exact WAV hash for a run and regenerate/compare explicitly, never call a changed waveform identical.

Run two labelled paths: (a) direct prerecorded `RecordingResult` through real `process_recording_result` for backend stage isolation; (b) paced synthetic-frame source through the normal recorder/chunk/streaming/dispatcher path for capture/stop-to-visible measurement. The synthetic source replaces device acquisition only, preserves broker conversion and recorder semantics, and requires an explicit benchmark-only adapter. Direct upload endpoint (`server.py:4852`) does not certify capture/streaming/dispatch latency. No microphone, global key injection or active user's target app is needed.

Use a harness clock to start stop-request observation and await the correlated visible draft event, excluding the fixed utterance speaking time. Fail on empty/no-audio/error/different fixture input; verify draft correctness locally against recipe expectations without exporting draft text. Capture first-use separately; no forced warmups disguised as first-run. Load real STT and optional cleanup only in an explicit local benchmark invocation after implementation; CI remains fake. Freeze fixture/model/runtime/config/hardware/device/thread/cleanup/streaming/visibility metadata, baseline version and sample methodology in the benchmark-only report; no user profile paths or secrets.

Harness replaces human Accept and Send using the ordinary typed/draft endpoints in the disposable profile, with injected in-memory output and clipboard sinks by default. This runs real draft/policy/coordination code but substitutes the external-effect boundary; label output timing simulated. A disposable data root does not isolate the OS clipboard, foreground target or global hooks; even real copy-only overwrites the shared clipboard. Disable global hooks and actual clipboard/input/focus effects in the default harness. A separate explicitly enabled live qualification in an isolated Windows test session uses a controlled owned target and exact fixture revision to verify paste/readback and restore/skip behavior, with blind fallback typing and submission disabled. If an isolated session is unavailable, require a declared interactive test invocation and preserve all clipboard formats; do not silently mutate a live user's clipboard. Report capture, processing, render, accept/API and verified target phases separately. End-to-end qualification still needs physical microphone/driver and human UI checks on the owner laptop outside this synthetic-only harness.

One running benchmark job per isolated backend; bounded timeout, cancellation request and confirmed job termination before another run. `app/src/renderer/lib/latencyProbe.mjs:96` races a timeout without inherently stopping native work **V**: future F38 stage runners must return typed job handles/cancel and wait for terminal state, rather than overlapping timed-out loads. Utilities currently asks for `latencyProbeStages`/`runLatencyStage` (`app/src/renderer/features/utilitiesWorkspace.js:2426`, `:2431`) **V**; unavailable stays unavailable until real runners exist. STT/rewrite/TTS probe measurements are separate component experiments, not reconstructed dictation totals.

## 5. Verification contracts (future implementation)

- Fake-clock tests: exact span boundaries, nested vs exclusive accounting, out-of-order/duplicate events, skipped stage vs zero duration, lazy decoder consumption, lock wait vs load, recovery I/O, successful retry vs failure, stream overlap and failed/empty tail, cancel before/during each stage, no-audio, queue drops and delayed clipboard completion. Each record terminates once; late events after wipe/restart are ignored.
- Cross-clock tests: deliberately different epochs, asymmetric IPC delays, offset interval containment, drift/restart/suspend invalidation, missing renderer, hidden document and uncertainty crossing the budget. Never accept naive subtraction or first `renderDraft` call as visible placement.
- Privacy contract: secret canaries in transcript/audio metadata/prompts/errors/path/clipboard/profile/draft IDs; adversarial extra fields/stage names/reason strings and raw-log override. Serialize the new latency subtree in runtime, `/metrics`, diagnostics and support report; none may contain canaries, content hashes, precise lengths, real capture duration or persistent business IDs. Explicitly assert legacy recent fields never enter exports, while preserving their existing local endpoint compatibility until migration. Support export also omits ephemeral correlation IDs. Strict schema rejects unknowns. Verify no filesystem writes/network requests and no resurrection after wipe.
- CI fakes: injected recorder/frame provider, monotonic clocks, synthetic decoder iterator, recovery sink, draft store, rewrite service, publisher and output sink; no model, mic, graphics driver or target app. Existing `tests/test_pipeline_metrics.py` remains a compatibility test; pipeline fakes extend `tests/test_dictation_pipeline.py`. UI tests exercise correlated receipt/presentation plus unavailable paths. Integration local benchmark is a separate opt-in command.
- Bounded resource/overhead tests: cap buffers/contexts/event count, expiry and race-safe snapshots, malformed/oversize fields, slow/failing collector does not block production, percentile fixture and unsuccessful-sample counts. Run paired real local benchmark only after source tests pass; record on/off variance, not a single stopwatch sample.
